Qué es un Sistema Operativo¶

Personas: Mary Allen Wilkes (1937 - )

En los años 1959 a 1963, Participó en el proyecto LINC, un dispositivo enfocado en el procesamiento de datos en tiempo real en biomedicina. En ese proyecto, asumió la responsabilidad de escribir todo el software de sistema. Su principal aporte fue LAP6 (LINC Assembly Program 6), un entorno operativo y de programación interactiva Wilkes, 1970 (copia local). Fue el primer sistema operativo que estaba entre el hardware y los programas. (“Pioneers in Tech”). Además, al integrar al sistema LINC un editor de texto que utilizaba una pantalla y teclado, cimentó las bases de interacción con los sistemas de cómputo actuales (ver nota)

Un Sistema Operativo (SO) se define formalmente como la capa de software fundamental que actúa como intermediario crítico entre el hardware subyacente y las aplicaciones de usuario, gestionando de manera eficiente, equitativa y segura los recursos computacionales Silberschatz et al., 2018. Desde la perspectiva de la arquitectura de sistemas, el hardware provee las capacidades físicas primarias —tales como unidades de procesamiento, jerarquías de memoria, subsistemas de almacenamiento y dispositivos de entrada/salida—, mientras que los programas y aplicaciones definen los requerimientos funcionales y de rendimiento. El SO arbitra estas demandas mediante algoritmos de planificación (scheduling), control de concurrencia y políticas de asignación, determinando cómo se utilizan dichos recursos para resolver problemas computacionales complejos en entornos dinámicos.

Para lograr lo anterior, un SO debe proveer un conjunto de abstracciones del hardware a las aplicaciones que se ejecutan en el sistema. Estas abstracciones transforman los componentes físicos en entidades lógicas (por ejemplo, procesos e hilos en lugar de registros de CPU y ciclos de reloj; espacios de direcciones virtuales en lugar de celdas de memoria física; sistemas de archivos en lugar de bloques en discos magnéticos o de estado sólido). Como consecuencia directa de este diseño, distintos Sistemas Operativos definen diferentes modelos de abstracción sobre una misma arquitectura de hardware, priorizando aspectos específicos como el rendimiento en tiempo real, el aislamiento de seguridad, la eficiencia energética o la portabilidad Muralidhar et al., 2022.

Actualmente, las arquitecturas de cómputo se caracterizan por ser heterogéneas (procesadores multi-core, GPUs y TPUs) y estar implantados en entornos distribuidoss. Debido a esto, el rol de las abstracciones del SO es fundamental para el uso masivo de estos sistemas. Investigaciones recientes en el área de sistemas operativos Gill et al., 2024 Deng et al., 2024 destacan que la evolución de las interfaces de abstracción es importante para cerrar la brecha entre la complejidad del hardware emergente y las altas exigencias de rendimiento de las aplicaciones basadas inteligencia artificial a gran escala, por ejemplo.

Abstracciones del HW¶

Tal como se mencionó al principio de esta unidad, una de las principales tareas de un Sistema Operativo es facilitar el uso del hardware a través de técnicas que permiten ocultar los detalles de su funcionamiento y enfocarse en su uso. Uno de estos componentes es el procesador, que, como se vió en la sección Arquitectura de Von Neumann, nació como un elemento simple que permitía la ejecución de un sólo contexto de ejecución y ahora es un componente sofisticado que permite ejecutar en forma simultánea varios contextos.

Proceso¶

Un proceso es un programa en ejecución junto con todos los recursos que necesita para operar (espacio de memoria, registros de la CPU, identificadores y archivos abiertos). A diferencia de un programa —que es una estructura pasiva almacenada en un sistema de almacenamiento persistente como código ejecutable—, el proceso es una entidad activa que consume ciclos de procesador y memoria RAM gestionada por el sistema operativo.

Los componentes del procesos son almacenados en una estructura denominada PCB (ver Figura 3) contiene los siguientes elementos (entre otros):

  • Espacio de direcciones en memoria que contienen el Texto o Código (instrucciones en lenguaje máquina) que ejecutadas en la PU.

  • Espacio de direcciones en memoria para almacenar variables globales, variables locales (stack)

  • Espacio de direcciones en memoria para almacenar datos que el código solicita en forma dinámica (heap)

  • Identificador de proceso (PID), que es un número entero sin signo que identifica al proceso

  • Registros que está utilizando en la PU. El principal es el PC

  • Estado actual (Ready, Running, Blocked, Waiting)

  • Archivos utilizados

  • Información de gestión de recursos: Punteros de memoria asignada, descriptores de archivos abiertos y dispositivos de E/S en uso.

Unidad de procesamiento¶

Para facilitar su uso, el sistema operativo asume que un procesador puede ejecutar sólo un contexto de ejecución. Finalemente, desde el punto de vista de un Sistema Operativo, un procesador puede ejecutar sólo un contexto de ejecución. Este procesador, que se denomina LP, es una abstracción del procesador real. Un LP está asociado siempre a un HT. Como un HT puede ejecutar sólo un contexto, por transitividad, un LP puede ejecutar sólo un contexto de ejecución o thread. Este thread que se implementa en un LP dentro del Sistema Operativo, se llama KT.

Algunas de las PU actuales, son máquinas de Neumann modificadas que pueden ejecutar dos o más Hardware Threads: MultiThreading. Debido a que desde el punto de vista del Sistema Operativo, siempre un LP está asociado a un HT, entonces el Sistema Operativo presenta 2 LP. Se debe tener en cuenta que el desempeño del HT que está relacionado con el MT tiene un desempeño menor que el MT original.

Como ejemplo, considere el sistema de la Figura 5, que tiene dos PU (por ejemplo, dos cores) que tienen SMT habilitado y pueden ejecutar hasta dos HT. Entonces, el hardware tiene una oferta de procesamiento de cuatro HT. Desde el punto de vista de un sistema operativo, estos HT los representa como cuatro LP. Desde el punto de vista de ejecución, el sistema operativo tiene la capacidad de ejecutar cuatro KT en forma simultánea.

Sistema Multiprogramados¶

Los sistemas multiprogramados son aquellos sistemas operativos diseñados para mantener varios procesos simultáneamente en la memoria principal (RAM), alternando la ejecución de la PU entre ellos para maximizar su uso.

Surgieron históricamente para superar la ineficiencia del procesamiento por lotes (batch) monoprogramado, donde la PU permanecía inactiva (idle) durante ciertos periodos cada vez que un programa realizaba una operación de I/O.

Mecanismo de funcionamiento¶

  • Varios programas ejecutables residen al mismo tiempo en distintas particiones o regiones de la memoria RAM.

  • La PU comienza ejecutando las instrucciones de un proceso.

  • Cuando ese proceso solicita una operación de E/S lenta (como leer del disco o esperar datos de red), el sistema operativo suspende su ejecución.

  • En lugar de dejar la PU sin uso, el scheduler realiza un cambio de contexto y asigna el procesador a otro proceso que esté listo para ejecutarse.

  • Al completarse la E/S del proceso original, este vuelve al estado de listo para competir nuevamente por la CPU.

Requisitos y características clave¶

  • Gestión de memoria: Requiere técnicas de particionamiento, reubicación y protección de memoria para evitar que un proceso altere o lea indebidamente el espacio de otro o del kernel.

  • Planificación de la PU (PU Scheduling): el kernel necesita algoritmos para determinar qué proceso puede utilizar la unidad de procesamiento.

  • Manejo de interrupciones: el hardware debe contar con mecanismos de interrupción para notificar al sistema operativo cuando un dispositivo de E/S ha terminado su transferencia.

Sistemas de Tiempo Compartido¶

Personas: Dennis Ritchie

Fue coautor del kernel original de Unix y el creador del lenguaje C (1972). Al reescribir el kernel de Unix en C en 1973 junto a Ken Thompson, convirtió a Unix en el primer sistema operativo moderno de tiempo compartido verdaderamente portable, desacoplándolo de una arquitectura de hardware específica.

Los sistemas de tiempo compartido (time-sharing systems) son sistemas operativos multiprogramados y multitarea diseñados para permitir que múltiples usuarios o procesos compartan los recursos de un procesador simultáneamente, proporcionando a cada uno la ilusión de tener una máquina dedicada.

A diferencia de la multiprogramación clásica —cuyo objetivo principal era maximizar la utilización de la CPU conmutando tareas solo cuando ocurría una operación de Entrada/Salida—, el tiempo compartido busca minimizar el tiempo de respuesta y permitir la interactividad directa en tiempo real.

Principio de funcionamiento¶

  • Ventana de tiempo (Quantum o Time Slice): La PU se asigna a un proceso listo durante una fracción fija y muy breve de tiempo (típicamente entre 10 y 100 milisegundos).

  • Interrupción por reloj: Un temporizador por hardware genera una interrupción periódica. Si el proceso no termina o no se bloquea antes de que expire su cuanto, el hardware transfiere el control al sistema operativo.

  • Cambio de contexto (Context Switch): El kernel guarda el estado de los registros y el contador de programa (PC) del proceso actual en su PCB, selecciona el siguiente proceso listo mediante un algoritmo como Round Robin, y restaura su contexto.

  • Ilusión de simultaneidad: Dado que la alternancia ocurre decenas o cientos de veces por segundo, el retraso es imperceptible para un operador humano interactuando a través de una terminal o interfaz de usuario.

Requisitos de hardware y arquitectura¶

  • Reloj programable e interrupciones periódicas: Para forzar la expulsión del proceso en ejecución (planificación apropiativa o preemptive).

  • Protección de memoria: Registros base/límite o unidades de gestión de memoria (MMU) con paginación para aislar los espacios de direcciones entre usuarios.

  • Modos de ejecución (Dual Mode): Distinción por hardware entre modo usuario (user mode) y modo privilegiado (kernel mode) para evitar instrucciones privilegiadas no autorizadas.

  • Memoria virtual: Permite mantener activos más programas que la capacidad física de la memoria RAM mediante mecanismos de intercambio (swapping) o paginación bajo demanda.

Operación dual de un Sistema Operativo¶

El modo dual es un mecanismo implementado en el procesador por hardware que permite evitar que distintos procesos interfieran entre sí y que los procesos no acceden diractamente a los recursos de hardware del sistema computacional. Separa la ejecución en al menos dos niveles de privilegio: modo usuario y modo kernel.

Modo Usuario (User Mode):¶

Es el estado en el que corren los procesos y aplicaciones del usuario (navegadores, editores de texto, compiladores, etc.). El repertorio de instrucciones está restringido: el código no tiene acceso directo a la memoria física ni a los periféricos de Entrada/Salida (E/S). Si una instrucción necesita utilizar el hardware, ésta debe generar una interrupción o syscall para transferir el control al Sistema Operativo.

Modo Núcleo (Kernel Mode):¶

Es el estado en el que corre el núcleo (kernel) del sistema operativo. La PU tiene acceso total y sin restricciones a todo el espacio de direcciones, periféricos y registros de control de la arquitectura. Solo en este modo pueden ejecutarse instrucciones privilegiadas (como manipular la tabla de páginas de la MMU, deshabilitar interrupciones, programar el temporizador del sistema o enviar comandos directos a los buses de hardware).
